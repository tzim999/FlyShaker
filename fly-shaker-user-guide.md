# Fly Shaker User Guide

## 1. System Overview

The Fly Shaker is an open-source vibration stimulus system for Drosophila behavioral experiments. It consists of an ESP32 microcontroller, a speaker-based shaker platform, an audio amplifier, an MCP6004 output buffer, an ADXL345 accelerometer, and a Python control program communicating over USB. The host computer is responsible for experiment logic, video acquisition, fly tracking, sleep detection, and data logging. The ESP32 is responsible for deterministic real-time waveform generation, timing, protocol execution, and accelerometer acquisition. This division keeps timing independent of the host computer's operating system and processing load.

The vibration waveform is generated by the ESP32 DAC, buffered by a unity-gain op-amp, AC-coupled into an external audio amplifier, and applied to a loudspeaker supporting the fly platform. The DAC idles at midscale (127) whenever stimulation is inactive.

## 2. Protocol Definition

| Parameter | Units | Typical Values | Description |
|---|---|---|---|
| Frequency | Hz | 20–200 | Square-wave frequency. |
| Amplitude | DAC counts | -30 to +30 | Active-level offset from DAC baseline 127; sign determines polarity. |
| Duty Cycle | % | 1–99 | Percent of each cycle spent at the active level. |
| Burst Active | s | 0.2–5 | Duration of one vibration burst. |
| Burst Silence | s | 0–10 | Silent interval after each burst. |
| Sequence Active | s | 5–300 | Total duration of repeated burst/silence cycles. |
| Sequence Silence | s | 0–3600 | Silent interval before the next sequence. |
| Session Duration | s | 0.010–2.592e6 | Overall experiment duration; maximum 30 days. |

**Amplitude note:** Amplitude is specified as a signed DAC offset from the
idle value of 127. Positive values produce an initial positive-going
waveform and negative values reverse the polarity. A minimum/maximum range
may be specified; one value is randomly selected from that range for each
burst. Approximately 13 mV corresponds to one DAC count at a nominal 3.3 V
DAC range. Thus 30 counts corresponds to approximately 0.39 V of DAC-level
change. Negative amplitudes can be useful when the direction of the initial
mechanical impulse is important, such as for single-cycle stimuli.

**AC-coupling note:** The ESP32 DAC idles at midscale (127). The DAC signal
is AC-coupled before the external amplifier, removing the DC offset. With no
stimulus active, the amplifier input therefore settles to approximately 0 V.


### Timing Hierarchy

```text
Session
└── Sequence
    ├── Burst Active
    ├── Burst Silence
    └── (repeats)
```

A sequence repeatedly alternates Burst Active and Burst Silence until the Sequence Active time expires. After Sequence Silence, the next sequence begins. Sequences repeat until the Session Duration expires.

### Randomization

Each protocol parameter may be specified as either a fixed value or a minimum/maximum range. If a range is supplied, a random value is selected at the beginning of each burst. This reduces habituation while maintaining deterministic execution by the ESP32.

## 3. Using the Fly Shaker with a Vision System

The recommended architecture is to let the vision software determine when stimulation should occur, while the ESP32 determines how stimulation is delivered. The host computer analyzes video frames, tracks each fly, estimates sleep state, and sends simple serial commands to the ESP32.

Processing pipeline:  
Camera → Video Capture → Fly Detection → Tracking → Sleep Detection → Decision Logic → USB Serial → ESP32 Fly Shaker

### Python Example

```python
import serial

ser = serial.Serial("COM5", 115200, timeout=1)
ser.dtr = False
ser.rts = False

while experiment_running:
    frame = camera.read()
    flies = detect_flies(frame)
    sleeping = analyze_sleep(flies)
    if sleeping:
        ser.write(b"START\n")
    else:
        ser.write(b"STOP\n")
```

The ESP32 executes the downloaded protocol locally after receiving START. The host computer remains free to continue image acquisition and analysis while the shaker timing proceeds independently. When stimulation is no longer required, the host sends STOP, returning the DAC to its idle state.
